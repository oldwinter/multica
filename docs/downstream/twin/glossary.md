# Twin Glossary

The entries below retain the original names only to make the provenance record
auditable. Multica-facing terminology may be adapted at implementation time.

| Harness term | Status | Multica interpretation |
| --- | --- | --- |
| Twin | adopted | Evidence-backed, reviewable personal-work artifact. |
| Possession | out-of-scope | No direct downstream domain object. |
| Injection Surface | adapted | Future runtime integration contract, not legacy daemon behavior. |
| Briefing | adapted | Bounded task context for an agent. |
| Egress | adopted | Explicit external-effect policy and record. |
| Host | out-of-scope | Legacy execution-container vocabulary. |
| Runtime | adapted | Existing Multica runtime concepts remain authoritative. |
| Brain | out-of-scope | No fixed Claude-Code brain is adopted. |
| Topic | adapted | Issue-backed collaboration flow. |
| Dispatch | adapted | Agent assignment and execution initiation. |
| Run | adapted | Execution record associated with delegated work. |
| Blocking Ask | adapted | Human decision gate for sensitive work. |
| Hard Stop | adapted | Explicit execution cancellation control. |
| Sign-off | adopted | Human review gate for Twin changes. |
| Execution Summary | adapted | Durable execution evidence for later review. |
| Deposition | adopted | Reviewable incremental learning proposal. |
| Local-Only | adopted | Source policy that prevents remote use. |
| Egress Ledger | adapted | Inspectable external-effect record. |
| Scan Escalation | adapted | Sensitive-content policy elevation. |
| L0 Raw Materials | adapted | Source evidence with provenance. |
| Persona | adapted | Evidence-backed preference assertions, never an unreviewed identity claim. |
| Skill | adapted | Reviewable procedural guidance. |

The legacy distinctions between on-screen and internal terms are retained in
the matrix only. They do not override Multica's established product language.
